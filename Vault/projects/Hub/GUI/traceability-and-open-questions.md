## Confidence levels

### High confidence

- Route names and route-level role guards.
- Main-menu entries and role filtering.
- Existence of search, create, edit, view, preview, panel, and modal screen
  patterns.
- API service and endpoint families in generated client code.
- Shared shell, interceptor, notification, and configuration behavior.

### Medium confidence

- Exact screen labels and field ordering.
- Which related panels appear for every record subtype.
- Which widget configurations are enabled in each environment.
- Whether a generated API service is used by a visible screen, an integration,
  an administration feature, or a future screen.

### Requires product or SME confirmation

- Whether source-derived client behavior is approved business policy.
- Status vocabulary and transition meaning where client and server enums may
  drift.
- Required fields and workflow steps for every service line and market.
- The intended user experience for errors, empty states, and exceptional paths.

## Open UX questions

1. Which screens and panels are used most frequently by each user role?
2. Which layouts, columns, tabs, and fields are mandatory versus configurable?
3. What responsive behavior is required beyond the current mobile menu mode?
4. Which browser support is required now that the current GUI favors Chrome?
5. Which keyboard, accessibility, and screen-reader behaviors are required?
6. Which visual assets, branding, icons, and report previews must be retained?
7. Which workflows need unsaved-change warnings or draft recovery?
8. Which long-running operations need progress, cancellation, or resumability?

## Open behavioral questions

1. Which client-side defaults and calculations are contractual?
2. Which status transitions require a hard confirmation step?
3. What are the exact refresh and event rules after each command?
4. Which attachment visibility and document actions are role restricted?
5. What are the concurrency and stale-data rules when two users edit a record?
6. What should the user see when an asynchronous integration is pending or
   fails?

## Documentation limits

This set documents the GUI as observed in source. It does not replace:

- a visual walkthrough with representative users;
- a complete design-system inventory;
- an OpenAPI contract;
- accessibility testing;
- browser/device testing;
- product acceptance criteria;
- production configuration and operational runbooks.

The existing [Planning README](../Planning%20%26%20Tracking/README.md) records
the outstanding SME and detailed UX review work.
