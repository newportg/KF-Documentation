    Page parity specifications

    This directory is the page-by-page specification for reproducing the current Hub GUI. The page contracts are organized by user-facing domain rather than Angular module.

    Current documents

    Document Coverage
    Route inventory Application routes, page families, and source entry points
    Core form specifications First source-derived field and section pass for Contact, Property, Activity, Requirement, and Tenancy forms
    Dashboard Dashboard widgets, drill-downs, calendar, tasks, and notifications
    Contact Contact search, duplicate check, edit, view, and relationships
    Property Property search, add/edit, hierarchy, attributes, and view
    Activity Activity search, context-sensitive forms, state changes, and view
    Requirement Requirement search, form, matching, and progression
    Tenancy Tenancy search, form, progression, renewal, and view
    Company Company search, create/edit, view, and related lists
    Offer Offer add/edit, view, preview, and status behavior
    Instruction, pitch, and referral Search, edit/view, and action-card workflows
    Marketing lists, reports, and administration Marketing-list, report, administration, and configuration screens

    Required page document format

    Every page document should use the following sections:

    # Page name
## Route and entry points
## Page regions and navigation
## Tabs, panels, dialogs, and child screens
## Fields and controls
## Defaults and conditional visibility
## Validation and error messages
## Commands and API operations
## Loading, empty, and refresh states
## Dirty navigation behavior
## Layout and responsive rules
## Source evidence

    Extraction rule

    Field names and labels must be captured from the page template, component, shared control configuration, translation key, and resolver/configuration source. A field should not be documented as required merely because it appears on screen; the requirement must be evidenced by configuration, validation code, or server validation.
